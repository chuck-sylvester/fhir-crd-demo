{# ------------------------------------------------------------------------- cds_cards.html — CDS Cards partial (HTMX swap fragment) ------------------------------------------------------------------------- This template is a PARTIAL: it does NOT extend base.html and contains no , , or tags. It returns only the markup that will be inserted into the existing DOM by HTMX. HOW THIS PARTIAL IS USED ------------------------- The "Check Coverage Requirements" button on patient_chart.html carries: hx-post="/orders/colonoscopy/crd" hx-target="#cds-cards-panel" hx-swap="innerHTML" When clicked, HTMX POSTs to the trigger_crd route in clinician.py, which assembles the CDS Hooks request, calls the payer, and returns this rendered partial. HTMX then replaces the innerHTML of #cds-cards-panel with the response — no page reload occurs. CONTEXT VARIABLES PROVIDED BY routes/clinician.py -> trigger_crd() ------------------------------------------------------------------- cards (list[CdsCard]) — list of CdsCard Pydantic model instances. Empty list when the payer returned no cards or when a payer error occurred. error (str | None) — human-readable error message when the payer call failed; None on success. ACCESSING PYDANTIC MODEL FIELDS IN JINJA2 ------------------------------------------ Pydantic model instances expose their fields as object attributes. Jinja2's dot notation works for both dict key access and attribute access, so {{ card.summary }} works whether `card` is a dict or a Pydantic model. The relevant fields from models.py are: card.summary (str) — short headline required by CDS Hooks card.indicator (str) — "info", "warning", or "critical" card.source (CdsSource) card.source.label (str) — payer name or rule set label card.source.url (str|None)— optional link to coverage policy card.detail (str|None) — extended guidance; may be Markdown card.links (list[CdsLink]) link.label (str) link.url (str) link.type (str) — "absolute" or "smart" TAILWIND CSS AND HTMX ---------------------- Tailwind CDN is loaded in base.html. When this partial is injected into the DOM by HTMX, the CDN Play script's MutationObserver detects the new nodes and applies styles to any Tailwind classes it finds. Dynamically inserted content is therefore styled correctly. One important constraint: class names must appear as complete, unbroken strings in the source. A class built by concatenation such as "border-" + "blue-400" would not be recognized. The dict below uses full literal class names to satisfy this requirement. ------------------------------------------------------------------------- #} {# ========================================================================== INDICATOR STYLE MAP ========================================================================== Maps each CDS Hooks indicator value to the Tailwind classes needed to color the card's left border and indicator badge. JINJA2 {% set %} WITH A DICT ----------------------------- {% set variable = { ... } %} creates a local variable in the template. Jinja2 dicts use the same Python literal syntax — string keys in quotes, colon separating key and value, comma between entries. Values are accessed with dot notation (s.border) or bracket notation (s["border"]) — both styles work in Jinja2. Defining the mapping once here and referencing it in the loop below keeps related styles together and avoids repeating an if/elif chain inside every card's markup. ========================================================================== #} {% set styles = { "info": { "border": "border-blue-400", "badge_bg": "bg-blue-100", "badge_text": "text-blue-800", "label": "Info" }, "warning": { "border": "border-amber-400", "badge_bg": "bg-amber-100", "badge_text": "text-amber-800", "label": "Warning" }, "critical": { "border": "border-red-400", "badge_bg": "bg-red-100", "badge_text": "text-red-800", "label": "Critical" } } %} {# ========================================================================== ERROR STATE ========================================================================== Displayed when the payer call failed — either the service was unreachable (httpx.RequestError) or it returned a non-2xx HTTP status (httpx.HTTPStatusError). The `error` variable is a plain string set by the route handler; `cards` will be an empty list in this branch. WHY THE ROUTE RETURNS HTTP 200 ON PAYER ERRORS ------------------------------------------------ HTMX only performs an innerHTML swap when the server responds with a 2xx status. If the route returned HTTP 503 or 502, HTMX would treat the response as an error, leave #cds-cards-panel empty, and the clinician would see no feedback. Returning 200 with an error message in the HTML lets HTMX insert the message so the clinician knows what went wrong. ========================================================================== #} {% if error %}
